## 2026-07-25 · 代金二分：自用券 / 分发券

### D-P1-4 产品二分（大股东确认）

- **决定**：代金体系拆成两类，**创建时二选一**，**核销时扫码自动分支**（店员不再选手动账本）。
  1. **自用券**  
     - 场景：集团/本店自用预付；**同企业下多门店可共用**（非全网开放互核）。  
     - 资金：**售出即归经营主体**（现金或店收）；**平台不做 Transfer / 不进可用·冻结·提现**。  
     - 奖励：**无**卖券佣金。  
     - 核销：记 **门店 + 金额/张**，只销权益，**不再分账入账**。  
     - 分店清算：靠 **核销报表** / 集团内部处理；**不做**「核销时自动转账」（无冻结池、易已提现、对账难）。  
  2. **分发券**  
     - 场景：分享、渠道、活动、抽奖等对外分发。  
     - 资金：维持现方案——**平台托管 → 核销分账 → 冻结 T+1 → 可提现**。  
     - 可配置佣金 / 奖池等。  
- **命名**：对外/店员统一 **自用券 · 分发券**（内部枚举建议 `self_use` / `distribution`）。  
- **抽奖**：挂在 **分发券** 玩法下；自用默认不绑抽奖。  
- **UI 原则**：简单明了、美观大方；类型用 **强标签**（色+字）；账户中心 **两套数字分开**，禁止混成一个「余额」。  
- **不做什么（默认）**：自用核销自动 Stripe 转账；自用进 Token 可用/冻结；创建时模糊类型。

### D-P1-5 页面与心智（配套）

- **创建**：第一步强制选类型，对比一行说明「钱在哪 / 谁能核 / 有无佣金」。  
- **核销台**：统一扫码 → 展示大标签「自用」或「分发」→ 一键确认；成功文案区分「已核销（无二次入账）」vs「收入已入冻结」。  
- **账户/经营**：自用看「今日售出（已收款）+ 待核销 + 分店核销」；分发看「可用 / 冻结 / 提现」。  
- **详细 UI 规格**：`docs/roles/product/ui-voucher-dual-type.md`。

## 2026-07-19 · 消费者站 vs 商家站分离

### D-P1-3 入口分离

- **决定**：
  - **`/` = 消费者站**（默认）：买券抽奖叙事 + 用户注册/登录；**无**「我是消费者/商家」双 Tab。
  - **`/for-business` = 商家站**：入驻、发券、后台入口。
  - 消费者首页 **页脚** 一行链到商家站即可。
- **原因**：双 Tab 把「浏览身份」和「登录会话」缠在一起，商家登录点「免费注册」会被 middleware 踢回 `/business`。
- **规则**：商家会话下点用户注册/登录 → 先 `logout?next=用户注册/登录`。

## 2026-07-19 · 试点产品边界（大股东确认）

### D-P1-1 代金券 vs 抽奖：各是各的

- **决定**：
  1. **S$10 代金券** = 纯「折扣代金券」活动（`voucher_discount` / `voucher_sale`），**无抽奖**。
  2. **抽奖活动** = 独立「梦想大奖池」（`draw_standard` / `lucky_draw_v2`），购券面额为 **三档：S$50 / S$100 / S$200**。
  3. 两条活动 **分开创建、分开链接、分开购买、分开对账**。
- **不做什么**：不为了试点把 S$10 塞进抽奖三档；不把三档抽奖拆成「3 张纸质券」语义。
- **账目验收**：大股东各买 **1 笔 S$10 代金** + **1 笔抽奖任一档**，核对实付 / 余额 / 核销分账 / 奖池。

### D-P1-2 抽奖「3 档券」定义

- **决定**：**3 档 = 三种购券面额**（50 / 100 / 200），不是 3 个大奖名称。  
  大奖展示（iPad / iPhone / BYD 等）是奖池 UI，与档位无关。

## 2026-07-18 · I0

### D-P0-1 企业 vs 门店信息架构

- **决定**：企业账号进 **公司 Dashboard**；具体店务进入 `/business/stores/[id]`；**无全局「当前门店」切换**。店员账号绑定店，登录即本店。  
- **原因**：符合真实连锁组织；减少错误核销记错店。  
- **复盘**：试点店员是否需要更短路径（桌面书签到 scan）。

### D-P0-2 I0 范围

- **决定**：只保证 **注册 → 设置 → 门店 → 码/核销选店**；发券/抽奖「能点开不崩」即可，不深打磨。  
- **原因**：市场演示卡在 onboarding 比卡在奖池配置更致命。  

### D-P0-3 完成定义

- **决定**：完成 = `acceptance.md` 全绿，不是「合并了很多 PR」。
